
[程序原始产物行为验收]
涉及 C 输出时必须声明顶格字面量 ARTIFACT_CHECKS 列表（1到4项）。
可以只提交这一条声明，不必额外编写 unittest；程序实际编译和执行，不把零退出或空测试算通过。
kind 可为 c_expression 或 c_statement。共同字段为 id、kind、imports、setup、expression、variables、cases。
c_statement 额外提供 result_variable：输出赋值的变量名，必须不同于输入 variables。
imports 只写绝对 from 模块 import 名称；setup 只构造输入，不改写导入接口。
expression 必须直接调用仓库生成接口，不得 replace、包装、翻译或修补返回值。
程序保存完整原始 C 输出；表达式放入 return，语句原样放入驱动函数后读取 result_variable。
variables 是数值 double 输入变量；cases 为 {"values":[输入数值],"expected":独立预期数值}。
检查实际生成产物的正常值和关键边界；不能用待修接口自身生成 expected。
若需求只要求行为，不要额外约束 if/else、三元表达式、空白或排版。用户明确要求的文本/协议格式仍须检查。
语句声明示意：kind="c_statement", expression="render(x, assign_to='y')", result_variable="y"。
涉及多个公开调用时分别声明检查。不要把符号代入后的常数计算冒充生成代码的运行时边界测试。
仍可附加有需求依据的 unittest；已存在的测试不会被静默忽略，冻结后不得降低标准。
编译失败是缺陷证据；编译器缺失或配置错误是验收不可用，不能判成功。
只支持数值 C 表达式和结果赋值语句；其他产物类型明确报告缺口。
