# 自动返工与停止边界

工作内核把可纠正的问题返回同一工作模型继续处理，沿用当前任务、原始需求、验收、历史和预算。
四个 LangGraph 节点和单工作租约不变，不新增角色或第二套调度。

| 情况 | 行为 |
|---|---|
| 模型提交受阻报告、纯文字回复 | 保存原响应与反馈，重新规划；模型的判断本身不是外部障碍证明 |
| 参数、方案或验收草稿不合格 | 正常拒收并配对工具返回，给出修正要求；不执行被拒内容 |
| 重复计划 | 返回已处理提示，要求读取结果后修正，不重放原操作 |
| 已确定结束的普通命令失败、正式验收失败 | 保存回执后返工，累计验收次数与消耗 |
| 完整且用量已知的空回复或纯文字回复 | 逐笔核验已保存的请求、回复与用量，追加宿主预算快照和纠正要求；不伪造工具调用身份 |
| Token、回复输出或任务时间上限 | 保存断点与明确原因，等待人工继续 |
| 未知响应、未确认副作用、权限／原件／存储／隔离环境问题 | 保持安全停止，说明证据和恢复条件，不盲目重发 |
| 用户主动暂停、取消或关闭应用 | 继续执行原有失联与停止保护，确认所属执行停止后汇报 |
| 实际验收通过 | 正常交付完成；人工继续可沿原记录开启复查 |

默认不再设置工作模型调用次数上限。用户明确设置的调用、费用或禁用服务限制仍属于授权边界，不能自动放宽。
所有尝试的时间、轮次、Token、费用和未知预留累计保留。返工不能保证模型一定解出任务，也不能替代验收覆盖度判断。

预算是否耗尽、何时停止派发均由程序读取实际账本决定，模型的“预算用完”“已完成”或“停止”文字不能改变任务状态。
聊天工作入口与批量工作入口使用同一条持久化拒收路径。当前回复必须完整、用量已知且原生完成回执一致；
历史上经人工明确继续后保留的未知用量仍累计，不因当前回复已知而清零，也不把本次新未知当作旧授权的一部分。

模型响应可能在截止时刻之后才返回。完整响应先可靠保存，再检查剩余预算，超限时不开始新的验收或操作。
后续人工继续复用已保存响应，只请求真正需要的下一步，不重新收费请求同一份已完成结果。

## 任务版本边界

历史冻结内核和任务原件不在清理范围。新版宿主仅保留旧停止协议字段的读取、显示与命令投递，
让已绑定任务仍由自己的旧内核执行；这些字段不包含旧轮数停机的执行实现。

## 停止原因与诊断

停止前先确认所属执行者和容器状态。每个停止身份只汇报一次，说明实际原因及已知／未知结果。
读取一个从未登记、由模型猜测出来的记录路径属于可纠正参数错误；已登记原件丢失、读取权限失败仍必须停止。
验收拒收反馈给出具体阶段、来源或计数，保留冻结规则，不把缺失测试、夹具失败或未知归因放行。
