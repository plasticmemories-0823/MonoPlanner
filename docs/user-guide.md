# 使用与排障指南

本页对应 MonoPlanner 1.0.0 正式初版。首次使用见[项目首页](../README.md)；安装包应与版本说明对应，已有任务仍依赖绑定的内核与环境。

## 启动、退出与失联

启动不会调用模型或安装依赖。桌面窗口内置本机界面；浏览器也可打开 `http://127.0.0.1:3000/`。界面只连接启动器指定的本机服务，不支持远程服务地址。

正常关闭桌面窗口会停止接收新操作，尝试取消本实例的模型请求、工作及环境准备，并结束前后端与所属子进程。启动或重连未完成时也可退出；服务无响应时限时结束所属进程，不提供只关闭窗口、后台继续工作的模式。普通浏览器标签页不拥有服务，关闭标签页只关闭页面。

源码目录也可直接部署完整运行文件，以根目录的 `MonoPlanner.exe` 启动，不需要保留 `dist` 构建副本。需要沿用原数据目录时，可在根目录设置仅本机使用的 `launcher.local.json`，字段为 `version: 1` 和绝对路径 `state_directory`；显式 `MONOPLANER_STATE_DIR` 环境配置优先。该设置只选择已有数据位置，不复制、重置或合并数据库及凭据，不进入 Git 或便携分发。无效配置会拒绝启动，不静默切换到另一套历史；显式停止仍可执行。

当前受管执行持续续租，宿主、内核或消息循环失联后停止进一步派发；容器内独立看守在撤销或超时后结束入口。停止不是零延迟，已发生的写入不会回滚，服务商已收到的模型请求也不能证明停止计算或收费。外部启动的用户应用不归该看守终止。详见[失联保护](lifetime-safety.md)。

重新打开应用核对记录并收拢遗留执行，不自动发起模型请求。只有用户明确继续、原件及环境核验通过后才续接任务。完整响应、步骤和验收回执可复用；工具仅部分执行时先调查现场，未知费用预留不释放。旧协议任务不能自动套用新保护，当前没有通用自动迁移入口，见[崩溃恢复](crash-continuation.md)和[升级兼容](upgrade-compatibility.md)。

Docker 控制接口无响应时不能假定停止成功。界面必须核验实际状态；容器看守提供独立超时路径，仍需保留待核对记录，不能用“已发停止命令”代替确认。

## API Key、模型与网络

密钥由后端使用 Windows 当前用户的 DPAPI 加密保存，界面仅显示是否已配置。留空保存保留已有密钥，也可以替换或删除。`DEEPSEEK_API_KEY` 环境变量与项目 `.env` 是后备来源；删除界面密钥不会删除后备来源。

思考支持关闭、low、high、max，默认 high。主模型单次输出上限为 256,000 Token，包含思考；自动进度沿用用户所选模型配置，标题与上下文压缩使用各自的独立规则。DeepSeek API 跟随 Windows 当前生效的系统网络设置：启用系统代理时按代理及绕过规则连接，关闭后直连，也支持按地址解析 PAC。新设置作用于随后发出的请求，不重发已发出或结果未知的请求；代理连接失败会报错，不偷偷切换路线重试。联网默认关闭，不影响模型连接。模型、思考及联网设置在下个新任务生效，已有任务及恢复继续使用自己的配置。

工作与 Chatbot 统一使用 80% 上下文压缩策略，同时为输出及安全空间预留容量；当前默认配置在 678,464 个估算输入 Token 时同步生成摘要。最近原文和工具调用配对始终保留，摘要不改写原始记录；必要内容无法容纳时停止。摘要请求单独记录用量，暂停和结果未知不会自动重发。主输出上限保持 256,000 Token；输入计数是本地估算，不等于服务商精确 Token 数。

网页搜索和读取分别直接调用 DeepSeek Search／Fetch API，使用已配置的 DeepSeek 密钥。Search 返回标题、链接、摘要等结构化结果；Fetch 返回 Markdown，不再额外调用聊天模型，也不在本机下载或解析目标网页。查询原文及 URL 发送给 DeepSeek，API 连接跟随系统网络设置；联网开关继续控制工具执行。当前实现以每次 ¥0.005 记录非空成功请求的估算费用，空结果及已确认失败记为零；实际收费以服务商为准。结果未知时保留费用预留并停止，不自动重发。费用与模型 Token 分开记录。本机界面与后端通信始终直连。

环境下载在代理模式下，通过同一代理向 Cloudflare 的加密 DNS 查询目标域名，避免本机 DNS 异常导致下载被错误拦截；只发送域名及记录类型，不发送网页路径、模型密钥或聊天内容。解析结果仍须通过公网检查，失败不会跳过检查或改走直连。

## 工作与项目

### 聊天与编码

普通聊天无需工作目录。编码时启动 Docker Desktop，选择工作区：可以是已有项目，也可以是存放新项目的父目录。描述目标、限制和完成条件后，助手会提出简要方案及实际项目位置，询问是否按照这个计划开工；回答“开始”后才创建或绑定项目并执行。已经明确要求“按方案开始实现”或“请直接修改”时，不重复询问。选择目录本身不代表批准编码，“只讨论、不要保存”等限制优先。

> 帮我制作一个鹈鹕骑自行车的动画网页。

新项目默认在所选工作区下建立有名称的子文件夹，确认时会说明位置。明确要求“直接放在当前根目录”时可使用根目录；目录不必为空，也不必是 Git 仓库。修改已有项目时沿用该项目，重名的新目录不会被覆盖。其他独立 Git 子项目不参与本次源码、安装或执行；若项目明确依赖它们，程序会说明范围冲突，需要重新确认目标。不会自动初始化 Git，也不会因上层存在仓库就扩大选定范围。

回复达到输出上限时，程序保存收到的内容和用量并停止，不执行该回复中的工具。可以先询问停止原因，或点击“继续任务”。继续前会核验原记录、源码、验收和容器，已完成操作不会重跑；只有身份和隔离配置核验通过的原容器可以重新启动；崩溃缺少停止回执时，先停止原容器并保存恢复核验记录。继续属于新的模型请求，仍会产生费用，也不保证没有重复思考。

### 继续任务与继续复查

当前版本统一提供人工继续入口：点击“继续任务／继续复查”、在聊天中单独发送“继续／继续任务／继续复查”，或对独立 CLI 任务执行 `python -m agent.cli.tasks --state-dir <原记录目录> --continue`。纯继续指令由程序识别；疑问、否定、引用或附带新要求的消息仍按普通消息处理。

暂停、取消、模型报告受阻、参数拒收和运行异常均保留原记录，明确继续后先核验原件、权限和环境，再从原计划或修复边界推进。已经成功的任务进入新的复查轮，旧成功结果保留，不能冒充本轮复查结果。缺失或损坏的原件、内核或环境须先修复，继续按钮不能绕过这些条件。

调用、Token、时间或服务预算耗尽时，只给耗尽维度追加一批原始额度；零服务预算不会变成付费权限。新内核的普通验收失败直接返工，不再每三轮等待人工追加。旧任务仍由绑定内核执行其原规则。全部累计时间、轮数、Token、费用和未知预留保持；重复点击不重复追加。刷新、重启和普通补充不自动继续。

独立任务统一使用 `--continue`；旧验收轮次专用入口已删除。详见[人工继续原任务](unified-continuation.md)和[自动返工](automatic-rework.md)。

### 验收与进度展示


调查阶段可在只读副本中运行局部检查；源码修改须先提交完整验收，试跑并明确冻结后执行。新任务统一使用通用验收入口，不按题面报错、函数名或框架名称附加专用验收协议。首次生成验收必须提供 `execution_checks`：程序强制执行所声明产物的编译／语法检查与实际运行，不能选择只调用函数或直接运行未检查的二进制。当前支持 Python／Node／Shell 仓库入口和数值 C 表达式／赋值产物；生成代码必须编译生产入口返回的原始文本，不能以运行生成器本身代替。其它产物类型未接入时报告缺口，不降级放行。声明与验收一同试跑、冻结和恢复，详见 [受管真实执行验收](managed-execution.md)。

生成测试可使用内置 unittest 驱动或项目已有测试入口；编译与运行检查由任务依据公开需求纳入测试或用户固定命令。包含已移除专用验收字段的旧检查点须使用对应冻结源码，不能在新版自动删字段续跑。

Chatbot 与工作使用独立上下文，普通问答不进入工作请求；明确补充才交给工作内核。工作思考与操作从本地记录持续增量显示，结束后停止读取；断线只补读，不重发任务。工作到达关键阶段后，Chatbot 根据本地事实简短说明“我刚查到什么、完成了什么”；有记录依据时再说明下一步。自然语言汇报之间至少间隔 30 秒，思考和操作显示不受这个间隔限制；没有新事件不会空转调用。每次自动汇报最多调用模型 3 次，只能读取当前工作的事实和受控记录，不能操作任务。聊天、工作、进度与标题分别统计用量，自动汇报也产生模型费用。普通聊天与工作仍沿用所选思考程度和原有输出上限。

点击暂停会立即停止新操作派发，并尝试终止本任务的模型连接和容器进程，不等待写操作执行完。已发生的修改或删除不会自动撤销。界面只有确认终止后才显示已暂停；结果不明时保留容器和证据，核对前不能自动续跑。切换工作目录会暂停旧任务并新开对话。

模型自行制定的冻结验收可通过 `revise_acceptance` 带有效原文证据修订，包括测试输入、夹具、断言、用例、驱动、执行检查和自拟回归命令。原始需求、用户确认的交付约束和固定用户命令不可借此改写。程序精确核验引用及逐项改动，重新核对需求绑定，再在原始源码上试跑并重新冻结；旧版本、失败记录和全部累计用量保留。缺少证据时返回具体英文补证说明。协议及边界见 [原文证据与验收修订](acceptance-evidence.md)。

失联时停止派发与容器终止是不同阶段。当前受管执行持续续租，容器内看守在撤销或超时后结束所属入口；只有核验执行者和容器停止，界面才显示已暂停。不能以请求停止已发送或零退出码代替最终状态，见[失联保护](lifetime-safety.md)。


### Docker 执行环境

默认使用 **自动准备**。选目录只保存允许工作的范围，不触发下载；确认开工位置后，程序针对实际项目检查配置并复用环境，没有可用环境时才下载基础工具和声明的依赖。选好目录后，输入框上方就会显示“当前项目 · 环境配置”；尚未开工也可配置。已有工作时显示该工作的实际项目目录。查询、重试和高级配置都针对显示的目录，普通聊天和目录浏览不会触发安装。

- 基础环境包含 Python、Node.js、Git 和常用编译工具；空项目使用产品默认版本。
- Python 项目识别版本声明、requirements、pyproject、uv、Poetry 和 Pipfile 锁文件，自动准备支持 Python 3.9 及以上；Node.js 项目识别 package.json、版本声明及 npm、pnpm、Yarn 锁文件。也检查常见前后端子目录。
- 项目环境保存在本机。运行时、依赖及必要安装输入没有变化时直接复用；界面、注释或排版变化不会触发重建。依赖变化时为后续任务准备新环境。项目自己的 Windows 虚拟环境、node_modules 或已安装软件不会被直接复制进 Linux 环境。
- 安装材料按需要收集：无依赖目录不复制项目文件；普通依赖仅提供声明和锁文件；安装项目自身、本地包或执行安装脚本时，才补充相应项目源码。遵守项目忽略规则，明确引用的必要资料仍逐项核验。准备前核算文件数和大小，超限会说明具体路径及纳入原因。
- 普通源码修改可复用依赖环境；非可编辑本地包及安装脚本输入变化需要重新准备。
- 安装发生在一次性容器中的过滤副本，不在 Windows 上安装项目依赖。Node 依赖使用只读 Docker 数据卷；项目及调查副本可能出现空的 node_modules 挂载目录，不写入依赖内容。
- 首次执行绑定镜像 ID、容器和挂载；已有执行记录不更换环境。恢复时不会重新安装或重放操作。准备失败会保留记录；修复网络或项目配置后可重试准备，再继续尚未开始的任务。

Windows CMD／批处理项目可在这里点击 **安装 Wine**。程序在 Docker 中下载并验证 Wine CMD，显示安装状态，可取消或在失败后点击重试；不调用模型，也不向宿主安装 Wine。Chatbot 先检查当前项目的能力，缺少 Wine 会指引用户点击这个按钮；不能另起任务代装。安装完成后再次读取能力再确认开工。只有用户明确点击安装才能下载或更新 Wine，普通工作只能复用已安装环境。新建项目请先创建并选择实际项目目录，或使用当前已配置目录存放批处理。详见 [Wine CMD 兼容验收](wine-cmd.md)。

已有手动环境仍然保留，位于 **高级设置**。可以切回自动模式，选择只影响后续首次执行。自动准备不调用额外模型，也不使用评测题目的专用镜像。

当前自动准备主要覆盖上述 Python 和 Node.js 项目。项目需要私有凭据、外部数据库服务、特殊系统库、GPU 或 Windows 专有软件时，不能保证自动完成；程序会说明失败，不能跳过依赖或回退本机执行。未在项目中声明的依赖不会靠猜测安装。编码期间新增依赖应通过新的环境准备供后续任务使用，不在冻结验收中途更换运行条件。

自定义 Dockerfile、Conda 配置和没有锁文件的 Pipfile 暂不自动执行，可继续使用已有的高级环境配置。自动准备会隐藏本机 node_modules 并提供容器依赖，不适用于直接修改版本库中托管的 node_modules 源码。

准备阶段允许通过受控代理连接公网下载站点；正式编码、调查、验收和已有任务容器仍无网络。需要任意联网或宿主机 Docker 控制的脚本不属于当前支持范围。依赖下载与聊天工具栏的“联网搜索”开关相互独立。

构建授权、构建中的镜像下载和项目依赖下载通过准备期间的受控转发服务，跟随当前系统代理及 PAC 规则，无需填写 Clash 等软件的地址或端口。仅打开代理软件但未启用系统代理，不等于启用了系统代理；TUN 等系统网络路由由操作系统处理。首次取得构建工具镜像仍由 Docker Desktop 下载，遵循 Docker 自己已有的代理设置；若 Docker 使用手动代理，Windows 开关不能覆盖它。程序会在失败时说明这一环节，不修改用户的全局 Docker 设置，也不自动重复下载。

打开环境设置或点击重新连接时，只核对镜像、依赖和已有准备状态，不重新安装。已经停止或不存在的准备容器会更新状态；Docker 无响应或资源归属不一致时仍保留待核对提示。下载失败后需明确点击重新准备，不能通过刷新自动重试。

### 资料、文件与权限

**齿轮 → 额外可读资料** 可添加文件或目录。单文件只授权自身；添加资料不授予修改、执行或启动权限。移除授权无法撤回已发送的资料。

| 权限 | 行为 |
|---|---|
| 沙盒权限 | 默认；编码及已有任务在 Docker 中，禁止本机外部启动和目录外写入 |
| 风险询问 | 编码仍在 Docker 中；外部打开与明确的单文件操作需逐次批准 |
| 完全权限 | 本机文件操作与外部启动使用当前 Windows 用户权限，无逐次确认，不申请管理员权限 |

权限仅作用于当前对话，在执行边界生效，刷新和恢复保留；新对话默认沙盒。模型不能切换权限或批准自己。批准绑定操作、软件、目标及原件状态，重复点击不重复执行。

文本、代码、Markdown、HTML、常见图片和 PDF 可在隔离预览中查看，不自动发送给模型。外部打开不接受任意 Shell 或启动正文；软件自身写入不受编码容器约束。

### 进度与结果

点击确认后，Chatbot 会读取已保存的按钮结果和最新任务状态，不需要反复确认。普通进度依据已保存的事件和阶段，用简短文字说明正在做什么；验收完成并收尾后，立即显示完成通知及项目目录。询问“完成了吗”或文件位置应读取这些记录，不额外运行程序。

确实需要再运行已有程序时，会先展示入口和参数，点击确认后才执行。额外运行的状态不会抹去原编码任务已经通过的验收结果。

### 对话管理

首条消息保存后后台生成一次短标题，产生少量额外模型费用；失败保留临时标题。列表右键菜单可归档或删除；删除移入回收站，彻底删除需确认并清理关联记录及独占闲置环境。其他任务仍需使用的共享环境会保留。工作仓库和独立评测文件不随对话删除。发布前旧格式不再读取；受支持协议的旧任务由新版应用调用对应冻结内核继续，原件和累计用量不变；缺少当前失联保护的旧协议需单独明确迁移。

在齿轮菜单的空间与环境入口查看记录和资源占用。默认闲置缓存软预算为 20GiB，目标盘预留 5GiB；程序只回收自身拥有且无引用的缓存，不执行 Docker 全局清理。暂停和结果未知的任务仍占用必要空间；空间不足会停止新准备，不删除恢复证据。

源码或环境准备失败会立即显示原因，保留原现场；刷新、重新连接和普通问答不会重新复制或安装。需要重试环境时，展开“当前项目”再明确点击准备。新目录创建结果不明时不会重复创建或覆盖。目录范围检查有数量及时间边界，所选范围过大时会要求缩小位置；不会把整个资料盘静默复制到任务记录。

如果本地运行记录也无法写入，程序停止派发新工作和模型请求，并显示存储故障。暂停仍尝试终止本任务；记录或终止无法确认时显示待核对，不宣称暂停成功。释放磁盘空间不会自动重跑任务，需先核对现场。

## 数据与隐私

用户消息、读取的源码和资料、工具结果、必要历史及思考续接字段会发送给 DeepSeek；标题请求只使用首条公开用户消息。联网搜索发送查询，网页读取将 URL 发给 DeepSeek，由其联系对应站点。产品不是完全离线工具。

环境准备会向容器和软件包仓库请求所需版本；不向安装容器传递模型密钥或本机凭据。项目安装脚本和第三方软件包可能执行代码，只应打开可信项目。准备时使用过滤后的临时资料副本；材料清单和安装日志保存在本机环境记录中，不自动发送给模型。

| 便携版数据 | 默认位置 |
|---|---|
| 任务、设置、加密密钥、源码快照和执行记录 | `%LOCALAPPDATA%/MonoPlanner/Data/state/` |
| 会话、命令和公开事件 | 上述目录的 `application.sqlite3`；当前应用数据版本 2；从版本 1 迁移前备份 |
| 启动日志和加密实例凭证 | `%LOCALAPPDATA%/MonoPlanner/Data/` |
| 桌面缓存与界面偏好 | `%LOCALAPPDATA%/MonoPlanner/WebView2/` |
| 环境作业、所有者和资源索引 | 状态目录下的 `resources.sqlite3`；准备材料与安装日志位于 `managed-environments/` |

下载的环境镜像和依赖卷由 Docker 管理。清空 Docker 会删除它们：新任务可以重新准备，已绑定但丢失容器的旧任务不能自动重建。

本地完整记录可能包含源码、业务数据和个人路径，应妥善保护，运行时不要删除恢复记录。`MONOPLANER_STATE_DIR` 可指定任务与设置目录；从源码启动默认使用用户的 `.local/state/monoplaner`。

界面与会话服务仅监听回环地址，通过实例凭证、同源代理和浏览器会话保护，不要将它们暴露到公网或局域网。环境准备期间会另开临时下载转发端口供 Docker 访问；该端口要求本次准备的随机口令，只能访问公网下载目标，准备结束即关闭。这些措施不防御已经控制当前 Windows 用户或 Docker 的恶意程序，也不构成百分之百安全保证。详见 [安全说明](security.md)。

## 故障处理

| 问题 | 处理 |
|---|---|
| 页面无法连接 | 查看启动日志，使用“重新连接”只重试读取，不重发模型请求或修改 |
| 端口被占用 | 处理自己确认的占用程序，或从源码用独立端口启动；不关闭无关程序 |
| 未配置模型密钥 | 在设置中填写，检查当前用户及后备环境变量 |
| Docker 尚未就绪 | 启动 Docker Desktop，等待引擎就绪后重试准备 |
| 环境准备失败 | 检查网络及项目依赖文件，查看本地安装日志；确认原因后点击重试，不会重放编码任务 |
| 旧环境或容器已删除 | 新任务可重新准备；已绑定旧容器的任务须保留现场，不能自动替换 |
| 请求或操作结果不明 | 保留现场及未知预留；明确继续前核对完整响应、回执与部分改动，不盲目重复运行 |
| 显示正在停止／停止未确认 | 等待并核对所属执行者与容器；无法确认时不能当作已暂停，也不能直接启动另一轮修改 |
| 继续入口被拦住 | 按提示核对停止身份、原件、权限、内核与环境；旧协议可能需要明确迁移，不通过刷新或清空记录绕过 |
| 旧任务无法恢复 | 核对保存的内核包及原环境；不跨源码改写检查点，缺失资源不会自动替换 |

发布包未使用代码签名，是否允许运行应遵循自己的组织策略，不建议关闭系统防护。干净 Windows 环境的兼容性以发布说明中的实际验证范围为准。

## 源码开发入口

源码开发需要 Python 3.13、Node.js 和 pnpm 11.25.0：

```powershell
python -m venv .venv-web
.\.venv-web\Scripts\python.exe -m pip install -r requirements-dev.txt
pnpm --dir web install --frozen-lockfile
pnpm --dir web test
pnpm --dir web lint
pnpm --dir web build
.\.venv-web\Scripts\python.exe -m pytest tests -q
.\scripts\build-helpers.ps1
.\scripts\build-launcher.ps1
.\scripts\start-app.ps1 -NoBrowser
```

首次准备桌面 SDK 和便携运行时需要网络；发布包启动不下载或构建依赖。目录、CLI、内部工具协议、通用评测和打包方法见[开发文档](development.md)。回归测试、假模型服务及实验分析不由生产入口加载，也不进入发布包。
