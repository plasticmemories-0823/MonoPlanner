# 崩溃、卡住与停止确认

运行权限必须持续续租，不能只依赖程序退出时执行清理。正常退出和暂停仍先走原有取消、回执保存及所属资源停止流程。

| 层 | 失联处理 |
|---|---|
| 桌面消息循环 | 每 300 毫秒发一个本机事件；后端 8 秒未收到即进入退出流程。界面进程失败也退出并停止服务 |
| 应用派发循环 | 8 秒未推进时，工作控制通道发出暂停，不继续安排工作 |
| 宿主与固定内核 | 私有管道每秒心跳；8 秒失联停止新派发并取消所属工作，收尾卡住时结束内核进程 |
| 每个执行容器 | 独立脚本检查只读租约；连续 15 次每秒检查没有更新即结束入口，容器命名空间一并结束 |
| 准备、依赖复制和构建容器 | 使用同样的入口保护，保留原命令、参数、网络和资源限制 |

租约由拥有该执行的进程续写，位于项目和可写执行记录之外，以只读目录挂入容器。
任务不能写续租文件；失写、撤销、损坏或身份变化均停止续租。停止时先撤销租约，因此 Docker 控制接口失效也不依赖它完成最终停止。
恢复必须核验原容器、配置、停止状态和脚本身份，明确继续后才重新续租。

这里是有界超时停止，不是零延迟。实际退出时间还包括操作系统调度和核验时间；进程全被冻结时由仍在运行的容器自行超时。
宿主和内核同时崩溃也不需要重新打开应用才能触发容器停止。Docker 虚拟机本身停止执行期间，容器命令也不执行。

界面在原生停止规划但所属执行者尚未收尾时显示“正在停止”。只有工作桥接返回并核验所属容器停止，才显示“已暂停”。
停止命令返回零退出码还不够，仍需检查实际容器状态；核验失败明确显示停止未确认，不伪装为成功。

远端模型服务已经收到的请求无法由本机证明已撤销服务商计算或收费。此时本机停止进一步派发，保留未知用量和费用预留。
恢复仍需人工继续，核对完整响应与副作用回执，不能把未知结果当作未执行，也不自动重发。

这些保护适用于本基准创建的受管执行。外部启动的用户应用不归此机制终止；历史冻结任务不热改，缺少该协议时先显示迁移条件。
