# MonoPlanner 与 DSH：两轮固定子集评测总结

评测日期：2026-10-19 至 2026-10-20。

这两轮结果呈现出不同的取舍：MonoPlanner 在两组所选官方成绩中都多通过一题。SWE 五题中，它花了更多时间和费用；Bench 十二题中，它的所选结果路径累计时间和已知费用更低。

## SWE 五题

双方使用同一轮当前 Flash / high，DSH 为完整 sdk 配置，保留 25 项原生工具。MonoPlanner 五题全部通过；DSH 通过四题，未通过的是 Sympy。

MonoPlanner 的整题通过率高 20 个百分点，但累计解题时间约为 DSH 的 **4.66 倍**，统一单价下的已知费用约为 **2.06 倍**。增加的投入主要来自 Sympy 与 Django；在 Requests 一题，MonoPlanner 的有效解题时间和已知费用均低于 DSH。

Requests 两组均采用免费重评后的有效结果：目标检查 7/7、回归检查 112/112。首次评分中的网络配置错误已修复，重评使用原有候选补丁，没有重新调用模型解题。两组本轮用量均完整，无未知费用预留。

## Bench 十二题

双方解题请求使用 Flash / max，DSH 为 sdk-minimal。两组共同通过第 1、3、4、5、8、9 题；MonoPlanner 另外通过第 11 题 `vllm-deepseek-streaming`。

按选定最终结果的完整路径累计，MonoPlanner 的整题通过率高 **8.33 个百分点**，已知费用低约 **25.48%**，有效解题总时间短约 **25.41%**。这些汇总不表示它在每道题上都更快或更便宜；例如第 3、5、11 题，MonoPlanner 的累计时间更长。

MonoPlanner 第 3 题采用验收额度续跑后的官方通过，第 7 题采用最终补测成绩。相关前置解题和续接用量已累计；更早废弃的第 7 题独立尝试另列，其已知低谷费用为 ¥0.57966444。所选路径与废弃尝试的已知低谷费用合计为 ¥15.15000216。

Bench 仍有未完整返回用量的请求。所选路径保留的高峰费用预留为 DSH ¥2.05532576、MonoPlanner ¥16.19200000；MonoPlanner 废弃的第 7 题另保留 ¥4.04800000。预留没有计入已知费用，也没有按零费用处理。

## 如何理解这两轮结果

- 两轮是不同题集、不同 DSH 工具配置的双系统对照，分别计算通过率，不合并成一个总成绩，也不据此单独推断 high 与 max 的影响。
- 双方保留各自原生提示、工具、验收和停止机制。Bench 前六题曾并发，后续串行；不能把耗时差全部归因于架构。
- 通过与否以官方整题判定为准，部分检查通过或原生验收通过不代替官方成绩。Bench 第 8 题重复执行的测试按 11 个独立测试计数。
- 时间为累计有效解题时间，排除暂停、准备和官方评分。费用按已知用量计算统一低谷/高峰等价，思考包含在输出中；不是服务商实扣账单。
- 缓存率按 Token 加权；两份对照表均分别展示顶层任务首次请求与任务内后续请求，不将新任务称作服务商冷缓存。

在这两个固定子集上，MonoPlanner 的所选官方通过题数均更高；成本与速度的结果取决于题集和运行配置。SWE 展示了用更多投入取得更高通过数的取舍，Bench 展示了所选路径中更高通过数与更低已知费用并存的结果。
