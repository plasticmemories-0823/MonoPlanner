# 四节点工作图

工作图只注册 `search`、`plan`、`execute`、`accept` 四个业务节点，另有 LangGraph 的 START／END。

| 节点 | 职责 |
|---|---|
| search | 原文搜索与读取、边界词典、既有只读查询、隔离诊断 |
| plan | 原有模型决策、回复分类、计划校验、局部修复、需求版本与控制边界 |
| execute | 按已保存计划顺序执行修改及工作命令，保存逐项操作回执 |
| accept | 原始源码试跑、明确冻结、编译与实际消费、候选验收及独立回归 |

四节点是原有调度的分组，不是四个角色。允许回跳或跳过，不要求每轮走完四步，不增加模型请求。固定工具顺序、单一工作上下文、同线程租约和现有任务原件存储保持不变。节点不自动重试，也不启用另一套 LangGraph 检查点。

控制输入、拒收、恢复、收尾保留为内部函数。每个节点按已保存的下一操作选择阶段，不能重新排列步骤。已完成请求、操作和验收只补齐收尾，不重复执行。Token／时间、用户主动停止、安全边界、未知结果和原文修订仍由同一内核处理；普通失败、受阻报告、重复计划与验收失败直接返工，没有固定轮数停机。

独立离线对照保存于 `validation/requirements-four-node-rg-20261021-01/dispatch-before.json` 与 `dispatch-after.json`：成功和返工样例的模型请求数、操作事件顺序及结束状态逐项一致。需求绑定与检索接口是另两项行为改动，不能把整轮修改都描述为纯调度重构。
