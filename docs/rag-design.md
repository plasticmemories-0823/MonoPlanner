### Q8：按资料结构优先切分检索片段

用户选择 A（2026-10-17）：

- 代码按函数／类边界切分。
- 文档按标题与段落切分。

### Q9：较小片段，命中后按需补读

用户选择 A（2026-10-17）：

- 首版目标长度约 256 Token，单片硬上限 512 Token。
- 超长结构拆分时，相邻片段最多重叠 64 Token。
- 能在上限内容纳的完整函数、段落保持完整，不机械切到目标长度。
- 上限计入随片段发送的来源信息，并受最终选定 Embedding 模型的实际输入窗口约束。
- 禁止静默截断；超长内容按 Q8 拆分并保留父级引用。

以上是首版可调整参数，尚未证明最优；具体 Token 计数需与选定模型的分词器及必要特殊 Token 对齐。

### Q10：命中片段返回，上下文显式补读

2026-10-17 按用户要求替换自动父块展开，修复无关父块与返回膨胀：

- 精确搜索返回包含完整字面命中的原文窗口，不推测所属函数或自动附带整个类。
- 语义搜索返回实际检索到的同版本片段，不再自动补读父结构。
- 正文只保存在`results`，各个命中以`result_id`引用；同源重叠区间逐字合并，命中坐标不丢失。
- 原件、来源哈希与续查位置保留，需要周边上下文时由模型显式读取；不把片段冒充完整源码。
- 单次预算仍见 Q13；分页按命中数量前进，不按合并后的片段数前进。

### Q11：使用本地 Cross-Encoder 重排

### Q12：全套本地 RAG 共享 1 GiB 额外内存峰值预算

用户选择 A（2026-10-17）：

- 首版暂定整套 RAG 的额外内存峰值预算为 1 GiB，不是每个组件分别获得 1 GiB。
- 统计范围包括 Embedding、重排模型、加载与推理临时内存及索引缓存。
- 优先给编码任务和 Docker 留空间，通过限制并发、按需加载控制占用。
- 主机余量不足时，即使 RAG 尚未用满预算也要让路，按已确认规则降级。
- 具体模型必须实测选型；超预算则使用更小模型或降级，不自行提高预算。

该预算是首版约束，不代表已经验证所选模型能够装入，也不把模型文件大小当作运行内存占用。

### Q13：单次检索工具消息最多 8,192 个估算输入 Token

用户选择 A（2026-10-17）：

- 首版单次检索工具消息的完整内容上限为 8,192 个估算输入 Token。
- 预算包含原文、来源字段、自动补读、缺失说明和续读位置，不只计算正文。
- 先提供排名靠前的资料；需要时继续补查。
- 放不下的材料保留原件并提供续读位置，不偷偷截断，也不将已返回内容当作全部证据。
- 该数值是首版可调整默认，后续通过检索评测校准。
- 单次检索预算不等于整项任务费用上限，不改变既有上下文压缩规则。

用户选择 A（2026-10-17）：

### Q16：受限自动调参、灰度与回滚

用户选择 B，并明确以下硬约束（2026-10-17）：

- 单次单变量：每次只调整一个旋钮，禁止同批修改多个。
- 档位化小步：topK 每次 ±10%，权重每次 ±0.05，阈值每次 ±5%；chunk 目标长度只在 256／384／512 相邻档移动。
- 冻结题集门槛：至少 100–200 条固定 query，包含 hard case、无答案及权限边界；提升必须超过噪声，可使用 bootstrap／置信区间，不允许仅凭“高 0.2 分”生效。
- 多指标门禁：Recall@100 或 nDCG 提升，同时 faithfulness、引用精度、p95、内存及成本不得退化；权限／安全用例零回归。
- 先进行 shadow 评测，只记录而不生效；通过后再进入 5% 流量灰度，异常自动回滚。
- 设置冷却期，首版按 24 小时内最多一次生效变更处理。
- 不修改运行中任务，只影响新任务；配置版本化，差异可审计。
- 禁止自动修改 Embedding 模型／版本、索引重建策略、ACL、删除策略及引用校验规则。

自动候选继续遵守此前确认的内存、检索消息预算和权限边界，不能通过调参自行放宽这些约束。
chunk 档位指 Q9 的目标长度，不取消原有单片硬上限、来源信息计数和模型输入窗口保护。
单变量规则适用于每次候选变更，索引更新仍沿用既定策略；本项不授权变更索引重建策略。

语义忠实度评审职责见 Q20，评测回答生成及费用边界见 Q21。引用存在、检索相关性或旧配置的回答不能替代候选配置的生成与忠实度验证。
本轮仍处于设计访谈；没有启动自动调参、付费评测、模型下载或灰度发布。

## 设计收束与实施顺序

主要取舍已经确认，后续不再要求用户逐个选择可逆的实现参数。按以下顺序准备实施：

- 5% 灰度按新任务固定分组，运行中任务保持原配置。回滚停止把异常版本分配给后续新任务，不在运行中切换版本。
