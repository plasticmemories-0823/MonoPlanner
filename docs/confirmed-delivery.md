# 原始需求与交付物绑定

工作模型决定实现方案，用户确认的需求决定验收对象。原文、交付约束和确认关系分别保存，结构化约束不能代替原文。

## 开工与变更

聊天端通过 `get_requirement_sources` 取得保存的用户消息 ID 和完整正文，通过 `prepare_work` 提交交付方案。宿主核对原文引用，保存方案，并显示“确认此方案并执行”。只有用户的 `confirm_work` 控制可以消费该方案；模型工具调用、普通回复、后来的无关消息都不是确认。同一方案即使换命令 ID 再次确认，也不重复启动工作。

方案包含项目位置、交付物 ID、产物类型、目标运行环境、实际入口、需求行为、输入范围及原文引用。生成代码还绑定导入、原始调用、输入构造、变量和必须执行的输入。允许先只读调查以确定这些信息。用户在确认界面可检查实际调用与输入，而不是只确认摘要。

Python 仓库入口可通过 `python_module` 明确选择 `python -m 模块名`。源码入口仍指向对应模块 `.py` 或普通包的 `__main__.py`，确认界面同时列出运行方式和原参数。模块调用不会被自动降级为文件调用，旧记录的空缺字段继续表示原文件调用。

CLI 使用 `--requirements` 读取用户明确提供的 `targets` JSON。直接工作接口传入宿主构造的 `confirmed_requirements`；SWE 接线用同一协议读取实例到 targets 的映射。缺少确认只允许调查，不能开始修改或宣称验收通过。它们不从模型候选中自动推导“已确认”目标。

显式用户补充沿原 `supplement/user_updates` 通道进入工作。未确认的新补充立即使旧验收失效，工作在安全边界等待；聊天端据完整原文准备新方案。新版本追加原文，更新明确改变的目标，未改变的目标仍保留。用户明确取消某个交付物时，方案须通过 `withdrawals` 列出该目标和新用户原文，并在确认界面明确展示；漏列目标不会自动删除它。用户确认后重新试跑和冻结。旧验收、试跑、结果及已完成工作保留；轮数、耗时、Token、费用和固定用户命令不重置。补充或方案确认不能解除用户主动停止、未知结果或安全边界；新的确认版本不等于新的执行授权。

## 验收约束

每项 `execution_checks.requirement_id` 对应已确认目标；只有一个目标时空 ID 可以唯一绑定。宿主核对产物类型、运行环境、实际入口和输入构造，所有目标都必须覆盖。生成物不得改填为生产者源文件、邻近 API、替代文本或不支持的运行语言。

生成代码的固定执行链是：真实仓库生产入口 → 未替换的返回文本 → 对应编译器／语法检查器 → 实际运行 → 行为断言。编译生产者不能代替编译返回产物。仓库入口则编译或语法检查确认的同一文件，再执行原入口。固定用户命令和独立回归继续保留。

支持范围见[受管真实执行验收](managed-execution.md)。当前生成代码适配 C 数值表达式／语句，仓库入口适配 Python、Node、Shell，配置相应固定镜像后支持 [Wine CMD 兼容验收](wine-cmd.md)；缺少技术适配时必须报告能力缺口，不能改写已确认目标来绕过。绑定检查能拒绝结构化目标被替换，不能证明 Chatbot 提取了所有自然语言含义，也不能证明用户确认的预期必然正确。

凭据绑定完整原文、确认关系、需求版本和验收材料。在计划放行、原始试跑、冻结、执行和最终完成处核对。原件变化、来源被篡改或较新补充使凭据失效；未知请求和未配对操作仍停止，不重发。原文只追加，退休验收保留在任务 `requirements/history/`，恢复时核验其内容和引用。没有新增 Checkbot 或第二套检查点。


## 验收草稿错误反馈

需求绑定失败时，程序逐项返回 `execution_checks` 的具体字段路径、已确认值与当前值，并将相关输入数量错误一并指出。测试代码、驱动和执行声明的独立错误分别保留，不再合并成一个无法定位的文本错误。

`repair_work` 只能原子修改已报告的字段，其余工作保留。修正后的完整材料仍经过全部原有校验；这些反馈不提供新的测试答案，也不授予修改用户目标、固定命令或冻结验收的权限。缺少人类确认或所需运行环境不受支持时，依然报告缺口，不能把目标约束当作可修复字段。

修正后的调查计划接收成功时，其纠错草稿同时失效，原文件继续留档。单独读取尚未修好的草稿不会消耗它。只有当前单个 `repair_work` 明确引用有效草稿时，修正错误才附带该草稿的字段；多工具调用、错误草稿 ID 等协议错误不复用其它提交的纠错信息。重复计划停止规则保持。

完整结束、用量及缓存用量已知、没有正文或任何工具调用的空回复，可以收到一次宿主协议反馈，再消耗原任务预算请求修正。原回复原样保存，不伪造工具调用或执行回执，也不改变需求。这个机会在整个任务内最多一次，暂停和恢复不重置；再次空回复停止并保留。未知用量、截断、损坏的调用身份、在途或未配对操作、记录失败仍停止，不自动重放。历史任务仍要求对应冻结源码，不迁移旧检查点。
