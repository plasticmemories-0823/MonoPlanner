# 开工能力检查与停止原因汇报

Chatbot 负责确认需求和解释工作事实，工作内核负责实际执行。两者分别保存上下文；聊天中的说明不能批准工作、替换原始需求或修改验收。

## 开工前

Chatbot 先通过 `get_work_capabilities` 查询实际存在的验收适配器。`prepare_work` 和确认入口再次检查交付目标：没有对应适配器时拒收并说明缺口，不等工作模型开始以后才发现，也不把用户要求的产物改成其它语言。

适配器存在不代表项目依赖已经安装。环境准备仍需通过原有检查。说明文档属于交付行为，不应被声明为使用 `plain-text` 运行时的可执行入口。原生 Windows CMD/BAT 仍属于能力缺口；已配置 Wine 镜像的项目可明确选择 Wine CMD 兼容验收，范围与限制见[Wine CMD](wine-cmd.md)。不能将未经执行的脚本文本宣传为已经通过验收。

## 最新进度与完成通知

普通聊天每次请求前接收应用保存的最新任务与按钮事实，包含已确认、已应用和失败的操作。内部准备下一步仍是运行中；已确认的按钮不需要重复点击。当前运行命令与原编码任务的验收结果分别保留，不能相互覆盖。

验收完成并核验收尾后，程序立即发布一次简短完成通知和项目目录，不等待额外模型请求。重启可补发尚未显示的完成通知，不重跑任务。日常进度由已提交事件和当前阶段直接生成简短说明，不请求模型猜测活动；相同阶段不反复通知。发布前核对状态版本，不能把启动准备说成正在写文件。

普通聊天生成期间，如果任务刚好完成、停止或确认状态变化，旧草稿仍保留原件和用量，但不显示过期状态；补入新事实后重新回答，最多刷新两次，持续变化时显示程序事实。已完成的工作和请求不重放。

只查询状态或文件位置不会直接执行程序。Chatbot 如提出额外运行，必须展示固定入口和参数并得到按钮确认；重复确认不会重复启动。

## 停止之后

所属执行者完成收尾核验前保持“正在停止”。确认最终状态后，每个停止身份只产生一次汇报；重新继续后发生的新停止具有新的身份。Token／时间超限、已核验安全边界及用户主动停止进入这个入口。旧内核的历史停止仍可按原记录解释；新内核的模型受阻、普通拒收、重复计划、纯文字回复和验收失败直接返工，不制造暂停。

汇报读取状态、原生诊断和必要的操作输出，用用户的语言解释具体原因、已知结果、证据缺口和继续所需条件。模型汇报最多使用三次请求，最后一次强制组织答复而不再调用工具；失败或用量未知时不自动重发，以已保存原因显示兜底说明。关键存储故障仍按原有闭锁处理，不能伪称停止记录已经保存。

`read_work_record(record="diagnostics")` 只读当前会话关联任务，提供：

- 已提交检查点的状态、原因、最近计划拒收理由和验收摘要。当前计划已经提交的操作单列，避免停在验收阶段时只看到上一轮调查。
- 当前计划保存的验收报告与进程回执，仅投影计数、超时、退出码等字段；未完成提交的原件明确标注，不能据此绕过未知结果或重放。
- 中断来源、控制标识、异常类型与错误码，以及请求用量是否未知。
- 最近操作的原件引用；可继续分页读取已提交的结果和 stdout/stderr。
- 准备失败、停止和运行环境的保存回执，附读取时原件哈希并标明其历史性质。

停止汇报还读取宿主管理的最新已确认需求版本、确认身份和输入范围，并区分已确认与是否已接入工作内核。看不到私有测试正文只能限制覆盖度判断，不能把已经确认的用户选择重新说成待确认。

这些权限不包括其它任务、私有模型推理、凭据或完整冻结测试正文。没有检查点的准备失败也能读取诊断；查询不创建检查点或启动工作。

## 证据的含义

- `User interrupted` 的旧标签本身不能证明用户点击暂停，须核对实际控制命令及来源。
- `plan_rejected` 表示该次方案需要纠正，不能单凭它断言整题停止。
- 旧记录的 `task_blocked` 表示工作模型报告受阻，不等于程序独立证实了外部障碍；新内核将这种报告配对为返工反馈。
- 最近操作列表为空，不证明从未执行或没有生成文件。
- 一个错误码可能有多个成因。权限错误、共享句柄冲突、断网和用户暂停不能互相替代推断。
- 保存的停止回执不是新的实时容器检查；旧记录没有保存的底层异常无法事后补造。

## 存活监测修复

Windows 与 Docker 的共享文件句柄可能短暂阻止心跳文件原子替换。只针对 Windows 访问或共享冲突，在两秒内有界重试；持续失败仍停止续租并记录系统暂停原因。容器原有的十五次无更新检查保持不变。

管道心跳接收不再执行耗时状态读取或 Docker 停止回调。查询与停止回执各自串行处理，实际工作仍只有一条调度路径。已收到的停止回执交付后才返回最终结果；真正失联的八秒保护仍保留。

## 升级边界

聊天接口使用独立版本号。升级前检查原始历史和旧摘要，保存旧请求视图，再应用新的提示与工具；未经版本声明的规则变化、损坏记录及未知请求仍拒绝发送。

工作任务继续绑定自己的不可变内核，不热改旧内核或伪造恢复身份。既有任务需要更换内核时须显式迁移，原件及累计用量保留。
