# 容器资料检索

适用于当前正式版的新任务。进行中的任务保持自己的来源授权、环境绑定和源码身份；旧任务使用对应冻结源码，不在恢复时替换检索实现。

## 工具分工

工作提示要求定位已有源码、文档、日志和容器资料时使用 `submit_plan` 的 `search`。
已知位置仍使用 `read`，支持 `from_step` 和长行字节续读。Shell 保留编译、测试、
编辑、二进制和运行环境诊断，以及处理刚执行命令的输出。没有命令黑名单、自动
改写或运行时强制路由；离线测试不能证明真实模型必然遵守提示。

仅支持 exact 完整字面子串匹配，保留大小写、空白、重复文字和重叠命中。Python 扫描授权原件，旧版 BM25 自动排序。没有语义检索、检索模型或外部搜索进程；不会在环境启动时自动扫描。

## 路径和授权

| 路径 | 资料范围 |
|---|---|
| 项目相对路径 | 现有冻结项目源码 |
| `$record/...` | 当前任务已提交的允许操作原件 |
| `$container/system_include/usr/include/...` | 容器标准头文件 |
| `$container/toolchain_src/build/gcc-13.2.0/libstdc++-v3/src/...` | 经程序核验的工具链源码子树 |

`/usr/include`、`/usr/local/include` 默认登记为 `system_include`。其他可信根可以由
宿主设置入口的可选 `container_read_sources` 字段提供，经现有会话设置和工作交接
传给内核；模型工具没有修改此设置的能力。例如：

```json
{
  "container_read_sources": [
    {
      "namespace": "toolchain_src",
      "path": "/build/gcc-13.2.0/libstdc++-v3/src"
    }
  ]
}
```

该字段支持现有 `/settings` 接口以及会话 `runtime_settings`；不新增前端配置面板。
设置仅影响后续绑定的任务，不能改写进行中任务的配置和历史。只读挂载须由宿主
明确登记 `allow_mount: true`；可写挂载始终不自动授权。

模型显式请求未登记路径时，仅在 `/usr/src`、`/usr/local`、`/opt`、`/build` 内
核验具体 `src/source/sources/include/includes/headers/patches/doc/docs` 子树。
`/usr/src` 的具体源码子目录也可核验；宽泛根目录不允许。临时授权只属于当前任务，
终结时撤销；暂停和结果未知不被当作任务结束。已确认路径是本次启用的审计依据，
没有零结果后自动扩大范围或隐式切换模式。

固定范围外返回 `requires_authorization` 和具体路径，工作方须报告并等待宿主授权，
不能靠用户资料中的一句话、Shell 可访问性或模型自报批准加入清单。授权由宿主
更新设置并建立后续任务；当前版本不新增对话内“确认后自动授权目录”的按钮。

以下内容排除：`.env`、凭据、密钥、证书、`.git`、缓存、编译产物、运行输出目录、
特殊设备、隐藏评分材料、其他任务资料以及未经登记的挂载。文件类型、路径各段、
解析后的链接目标和可识别的秘密正文都会检查。`/agent-artifacts` 不整体开放，
日志通过原有 `$record` 白名单读取。

## 原件、版本与资源

- 固定 stdlib 探针只接受 `stat/list/read`，在已有运行容器中执行，不接收模型程序、
  不启动新容器、不下载镜像。探针使用隔离 Python，派发前后检查暂停，容器内另有
  最长 25 秒且早于宿主超时的截止计时。
- 来源绑定实际容器 ID、镜像 ID、挂载与已记录工具链版本；存在 RepoDigest 时一并
  保存。工具链版本未记录时明确标为 unavailable，以镜像和文件哈希识别内容，
  不伪造版本号或另执行未知编译器来探测。
- 每次请求核验当前文件。文件原地修改、容器重建或挂载变化会使旧来源版本及游标
  失效。搜索结果交付前再次核验所选原件；引用核验也检查实际来源。
- 来源枚举游标与命中分页游标分开。未完成清单时返回明确的继续位置和 incomplete，
  完成选定范围后才排序分页，不把部分扫描当成“没有命中”。
- 枚举按既有资料级预算限制：最多 10,000 份来源、32 MiB 扫描缓存；单次原件读取
  沿用父进程内存预算推导的 7.5 MiB 准入。超限明确要求缩小路径，不静默漏掉文件。
- 扫描缓存 TTL 为 600 秒，访问时清理过期派生文件；已完成扫描清单在结果交付前
  回收。只有实际交付或显式读取的原件进入永久内容哈希归档，相同字节只存一次。
- `/build` 来源标记 `from_build_tree` 和 `temporary`；相关性相同时排在稳定来源后，
  不删除精确命中。TTL 不删除原件，也不延长临时授权。
- 索引、消息、读取和空间保护沿用现有预算；共享读取预算仍为 50 KiB。没有把目录
  快照、完整镜像或运行时复制进任务记录。

## 离线验证

`test_container_rag_backend.py` 使用固定探针子进程和假 Docker；其他三组容器 RAG
测试用内存容器验证真实授权、检索、原件、读取、引用与恢复连接。它们不调用真实
模型、不操作正在使用的容器。Windows 无法创建符号链接或 FIFO 时相应用例跳过，
其余链接策略仍通过模拟协议验证；真实 Docker 性能及模型遵从率须另行实测。
