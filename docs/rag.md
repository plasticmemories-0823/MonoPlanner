# 原文检索

工作端 `search` 与聊天端 `retrieve_evidence` 共用 rg 扫描、自动 BM25 文件排序和原文引用。检索不调用模型。

| 场景 | 参数 | 结果 |
|---|---|---|
| 完整函数名、字段名、标识符 | `mode=exact, match=whole_word`（默认） | 完整字面查询，Unicode 词边界 |
| 报错原文、代码片段、名称或中文片段 | `mode=exact, match=substring` | 字面子串，不要求词边界 |
| 多个线索、尚不知道位置 | `mode=keywords, terms=[...], query=''` | 任一显式关键词命中；`match` 控制边界 |
| 已经找到位置，需要判断含义 | `read`／`read_file` | 读取对应原文上下文 |

查询区分大小写，保留内部标点、空白、多行和重叠匹配；不自动拆词、改写或补同义词。完整词字符包括 Unicode 字母、数字、组合标记、连接标点和连接控制字符。中文短语处于连续文字内部时，应明确选择 `substring`。关键词最多 16 项；同一位置的同一范围只记一次。

BM25 始终对 rg 已命中的文件排序，`k1=1.2, b=0.75`，多关键词累计得分。同分按来源优先级、路径、来源身份稳定排序；文件内按原文位置展示。排序不改变匹配集合，不用 Top-K 丢掉剩余结果。返回 `search_metrics`：扫描耗时、排序耗时、参与排序文件数及有界排名预览；这表示排序实际执行，不表示相关性必然正确。

继续页使用 `next_cursor`，不能同时改变查询、模式、边界方式、关键词、范围或权限。游标绑定原件版本、哈希和固定排序；变化后明确拒绝。索引只保存来源元数据，扫描结果临时落盘；按需读取原文窗口。大文件、超长行、二进制、不可解码原件、超时或资源不足会显式报告跳过或不完整，不能由此宣称零命中或资料不存在。

rg 只接收既有授权规则产生的固定原件文件清单。宿主资料直接扫描固定版本；容器资料先沿只读协议核验并取得原件，不向任务容器安装 rg。项目、额外只读资料、容器和允许的任务记录继续隔离。引用保留哈希、Unicode 坐标与原文；搜索片段不是完整函数或全文。

Windows 便携运行时固定为 ripgrep 15.2.0，位置为 `launcher/runtime/ripgrep`，校验清单在 `resources/ripgrep.json`，许可证随运行时保存。开发准备脚本为 `scripts/prepare-ripgrep.py`；运行时缺失或校验失败会报错，不回退 Codex 的工具目录，也不继承用户标准输入。

不提供 `semantic`、`regex` 或 `rank` 参数。旧向量、Embedding、神经重排、查询改写和后台模型链路保持删除。历史冻结源码、索引、共享缓存和评测原件不清理、不迁移；旧任务必须用对应冻结源码恢复。
