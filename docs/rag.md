# 原文检索

工作端 `search` 与聊天端 `retrieve_evidence` 共用纯文本检索：仅支持 `mode=exact`，用 Python 按完整字面子串扫描已授权原件，再用 BM25 排列命中文件。检索不调用模型，不启动外部搜索进程。

查询区分大小写，保留空白、标点、多行、公式和重复文字；不拆词、改写、化简或推断文件名。相互重叠及不同位置的命中分别保留。`query="echo echo"` 只寻找这个完整子串，不折叠为 `echo`。已找到位置后，用 `read`／`read_file` 读取原文上下文。

BM25 沿用原算法，`k1=1.2、b=0.75`：整个查询是一个词项，统计每份可读授权原件的 Unicode 字符长度与出现次数。按分数降序排列文件，同分按来源优先级、路径及来源身份稳定排序；文件内按原文位置展示。不用 Top-K 删除剩余匹配。

`path` 仅限定授权文件或目录。初始查询可设置 `offset`，默认 `limit=80`（1..1000）；继续页使用 `next_cursor`，不得改变查询、范围、优先级或原件版本。游标版本为 5，明确拒绝旧 rg 游标；旧任务仍由对应冻结内核执行。

每个命中窗口保留完整查询及最多前后各 96 个原文字符，受行边界限制；同版本重叠窗口合并。模型只收到一份正文、共享来源表及命中引用，单次工具消息含包装不超过 8,192 Token。片段不是完整函数或文件；其余匹配分页读取，不能把当前页当作全部证据。

权限、原文哈希、Unicode 坐标和容器只读协议保持。容器资料先按既有协议取得原件；项目、额外资料及允许的任务记录继续隔离。原件逐份读取，读取前及读取时核验共享 256 MiB 内存预算；当前整份文本读取上限由预留推导为 7.5 MiB，超限明确不完整，不静默截断。引用核验仍使用有界原件读取器。每次扫描有时间限制，取消、读取失败、不可解码、二进制、版本变化及资源不足都不能解释为资料不存在。

`match`、`terms`、`keywords`、`whole_word`、`semantic`、`regex`、`rank` 均不支持，显式拒收而不改成其它搜索。检索不依赖 rg、向量、Embedding、神经重排、查询改写或后台模型。来源目录和版本缓存仍保留。
