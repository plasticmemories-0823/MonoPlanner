# MonoPlanner 1.0.0

MonoPlanner 是面向 Windows 本机使用的编码助手。先与用户确认需求和验收对象，再在 Docker 中修改、运行和验证项目，保存可核对的操作、验收及恢复记录。目前支持 DeepSeek Flash。

> 这是 MonoPlanner 1.0.0 正式初版。当前功能、使用方式和验证边界见本文及配套文档；历史评测单独列示，不代表本版重新测得的成绩。

![MonoPlanner 工作界面](docs/assets/workspace.png)

## 怎么工作

1. **确认需求**：Chatbot 讨论目标、项目位置、交付物和输入范围，保存原文及确认关系；用户确认后才开工。
2. **调查并准备验收**：工作内核读取授权原文、检查项目，生成的验收先在原始源码上试跑，再明确冻结。
3. **执行与检查**：在绑定的 Docker 环境中修改代码，执行真实入口；生成代码须检查并运行真实生成物，保留独立回归。
4. **交付或继续**：展示验收结果及记录。普通失败自动按原规则返工；Token／时间超限、安全边界或用户主动停止后，由用户决定是否继续，原任务与累计消耗保留。

Chatbot 与工作内核分别保存上下文，普通问答不打断工作。工作内核由 LangGraph 调度：

| 阶段 | 主要职责 |
|---|---|
| 搜索 `search` | 原文检索、读取、边界提醒和隔离调查 |
| 计划 `plan` | 模型决策、计划校验、纠错与需求版本核对 |
| 执行 `execute` | 按已保存计划操作项目，逐项保存回执 |
| 验收 `accept` | 原始试跑、冻结、真实执行检查与候选回归 |

这是同一工作内核的四个阶段，可以按需回跳或跳过，不是四个独立角色，也不要求每轮依次执行。见[四节点流程](docs/work-graph.md)和[需求与交付物绑定](docs/confirmed-delivery.md)。

## 快速开始

| 项目 | 要求 |
|---|---|
| 系统 | Windows 11 x64，普通用户权限 |
| 桌面组件 | .NET Framework 4.8；优先使用系统 WebView2，包内提供备用运行时 |
| 模型 | DeepSeek API Key 及网络连接，调用按服务商规则计费 |
| 编码与已有任务 | 已安装并运行 Docker Desktop，使用 Linux 容器；自动准备需 Docker Engine 28 及以上 |
| 首次环境准备 | 可连接 Docker Hub 及项目依赖的公开下载站点；需要下载空间与时间 |

聊天、查询和预览无需 Docker。便携包包含 Python、Node.js、Git 和生产前端，日常使用无需安装这些工具或 pnpm。它不包含用户项目依赖、正式评测镜像或数据库。

1. 从 [Releases](https://github.com/plasticmemories-0823/MonoPlanner/releases) 下载 `MonoPlanner-1.0.0-Windows11-x64.zip` 和 `SHA256SUMS.txt`，用 PowerShell 的 `Get-FileHash` 核对 SHA-256。私有仓库需要访问权限。
2. 解压到新目录，双击 **MonoPlanner.exe**；不要与旧包覆盖混合。在 **齿轮 → API Key 设置** 中填写密钥。
3. 编码时启动 Docker Desktop，选择已有项目或新项目的父目录，描述目标、限制及完成条件。
4. 检查开工方案中的实际目录与交付目标，确认后执行。环境默认自动准备；CMD／批处理项目先展开输入框上方的 **当前项目 · 环境配置**，点击 **安装 Wine**。无需先创建任务，安装不调用模型；已有手动环境仍可在高级设置中选择。
5. 查看工作步骤、验收与累计用量。需要停止时点击暂停；停止确认后，点击 **继续任务／继续复查** 或在聊天中单独发送“继续”，核验后续接原任务。

启动本身不调用模型或安装项目依赖。首条消息的标题、模型对话、自动进度及联网工具可能产生费用，见[使用与排障指南](docs/user-guide.md)。

## 核心能力与边界

| 能力 | 当前行为 |
|---|---|
| 需求与验收约束 | 绑定用户确认的目标、真实入口和输入范围；模型不能自行换目标。模型自拟验收可凭有效原文证据修订，重新试跑并冻结 |
| 原文检索 | 完整查询按区分大小写的字面子串扫描，BM25 排列命中文件；保留原文引用与分页，不使用向量或检索模型 |
| 真实执行检查 | 生成验收声明编译／语法检查和实际消费过程，文字回复不能代替执行；用户固定验收命令保持原样 |
| 持久化与人工续跑 | 先保存原件与检查点，再登记索引；复用已确认完成的结果，部分执行先检查现场，不盲目重放 |
| 开工与停止解释 | 开工前核对实际验收能力；聊天读取最新按钮与任务事实，简短解释进度；验收完成后立即通知结果与目录，真正停止时说明具体原因 |
| 失联与暂停保护 | 停止新派发、尝试取消本地连接并终止所属执行；受管容器以持续续租和独立看守限制遗留执行，核验后才显示停止成功 |
| 环境与观察 | 自动准备并复用 Python／Node.js 项目依赖，展示工作步骤、Token、缓存和上下文用量；自动进度只读工作事实 |

使用时需要了解以下限制：

- 自动环境主要覆盖 Python／Node.js。生成验收的通用执行适配目前支持 Python／Node／Shell 仓库入口和数值 C 表达式／赋值产物，点击环境配置中的 **安装 Wine** 后，项目还可明确选择 [Wine CMD 兼容验收](docs/wine-cmd.md)，只验证实际执行的分支；其它类型会报告缺口。项目已有固定验收命令另行保留。私有服务、GPU、Windows 专有工具及任意原生项目构建不保证自动完成。
- 内部验收与[边界提醒词典](docs/boundary-hints.md)帮助检查已选择的行为，不能证明需求已完整覆盖，也不保证官方评分或所有边界通过。
- 暂停及失联停止有核验和超时过程，不能保证零延迟；已发生的修改不会自动撤销。外部用户应用不归容器看守终止，远端模型计算或收费也不能由本机证明已撤销。
- 继续可能产生新请求费用；未知用量和费用预留保留。Token／时间及用户明确设置的调用／费用额度耗尽后，经明确继续才追加一批原始额度。普通验收失败自动返工；累计值不清零，权限和原件校验不能绕过。
- 用户消息、读取的代码与资料等会发送给 DeepSeek；产品不是完全离线工具。默认沙盒，联网准备和外部打开有独立边界，见[安全与隐私](docs/security.md)。
- 新任务绑定当前内核；旧任务依赖原内核、原环境和完整记录。旧协议缺少失联保护时须明确迁移，丢失资源不能用新环境冒充恢复。

## 历史评测

历史冻结版本固定子集的最终官方结果（不代表当前源码复测成绩）：SWE 五题为 MonoPlanner **5/5**、DSH **4/5**；Bench 4.0 十二题为 MonoPlanner **7/12**、DSH **6/12**。两轮分别统计；SWE 中 MonoPlanner 总耗时与费用更高，Bench 所选结果路径的已知费用和累计时间更低。

- [两轮评测总结](docs/benchmarks/2026-10-20/README.md)
- [SWE 五题逐题对照](docs/benchmarks/2026-10-20/swe-five-comparison.md)
- [Bench 4.0 十二题逐题对照](docs/benchmarks/2026-10-20/terminal-bench4-twelve-comparison.md)

对照表包含最终官方验收与回归、完整路径解题时长、Token、缓存率、低谷/高峰费用及未知预留。SWE 使用 Requests 免费重评结果；Bench 包含第三题额度续跑与第七题最终补测，不能将两轮配置差异直接解释为单一架构或思考档位的作用。
